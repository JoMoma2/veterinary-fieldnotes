# Normal whole-shift extraction

`[shift_context] enabled=true` routes the ordinary `vet-pipeline run` and unattended workflow through the full-shift extractor after independent transcription. This replaces small per-recording extraction for new pending jobs. Existing completed work remains unchanged. Defaults for other installations/tests remain disabled; enable only with an installed compatible local model/tokenizer and tested hardware allocation.

Transcription has priority across the queued recordings. If any recording still needs transcription (including a resource deferral or exhausted error requiring attention), the coordinator does not start whole-shift extraction or question verification. Otherwise an LLM could occupy the GPU needed to finish ASR. Explicit transcription-review holds are terminal for this scheduling barrier; their raw output remains retained and cannot become accepted fact evidence. Once transcription has finished, existing shift groups are extracted sequentially with separate full-shift contexts. This does not infer actual shift boundaries from import dates or unreliable recorder clocks.

GPU admission allows up to eight samples for recent activity to settle and requires three consecutive quiet samples before starting. Client, memory, model/context and shared-use checks stay enforced; sustained activity still defers without consuming recording retries or unloading models. A brief busy sample therefore need not abandon an otherwise healthy transcription pass, while genuine contention remains protected.

The selected local Qwen3.8 27B profile uses 81,920 context tokens, 32,768 maximum generated tokens, 48 requested GPU layers and a three-hour request timeout. Settings are request-local, not global Ollama changes. Context includes the input, reasoning and answer. The output allowance applies separately to each index/detail request. The complete serialized prompt, schema and output reservation are checked before inference. Oversize context fails without truncating source; larger-than-budget shifts still require an explicit partitioning strategy.

`[shift_context]` supports `chat_template_path` / `chat_template_sha256`, `native_reasoning_effort`, `stream_responses` and decoding settings (`temperature`, `top_p`, `top_k`, `min_p`). The selected profile retains its pinned native template, xhigh template effort and thinking, temperature 1.0 / top-p .95 / top-k 20 / min-p 0. Streamed reasoning and replies remain private and recoverable. Historical experiment defaults remain available for compatibility; they do not select a production model. Template effort must be supported by the installed model/template.

Normal transcription also supports `kind="parakeet"`: pinned Parakeet TDT v3 weights, Silero VAD weights and transcribe.cpp library, with explicit discrete Vulkan GPU selection. It uses the comparison's denoised mono 16 kHz copies, CPU VAD settings, 30-second windows and one-second overlap. Originals, VAD exclusions, raw native replies and window checkpoints remain retained. Audio-window times are labelled when the model supplies no alignment. No-speech/invalid-timing output stays in review; speech detection does not establish silence or accuracy. The normal unattended validator accepts this installed backend without enabling automation or downloads.

One primary model makes an episode map and detailed source-grounded episode requests. Existing medical-only questions, five-repeat exclusion, uncertain speaker identity semantics and source-citation rejection remain active. Unreliable ASR can supply context but cannot become fact/question evidence. No extra AI reviewer, paid API or model download is introduced.

The detail contract adds reusable `knowledge_topics`: stable subject keys, readable source-supported accounts and exact citations. A bounded article naming index helps reuse existing subjects without loading the accumulated medical library. Case-only discussions can produce zero general articles/questions. Invalid topic citations are quarantined independently of otherwise useful details. The pipeline cannot guarantee semantic correctness from JSON/citation checks.

Accepted episodes save transactionally into the existing canonical SQLite/Markdown/JSON library: detailed multi-recording discussions, additive article updates, conservative explicit candidate cases, standalone medical flashcards and bidirectional source links. Species/diagnosis/outcome formal case fields remain unset pending review; recorded details are retained in cited narrative/facts instead of guessing those fields. New snapshots marked studyQuestionFormats="mixed-v1" can generate flashcards, multiple-choice or multiple-select. The prompt asks for variety when supported, without a quota; ambiguous options should remain flashcards or be omitted. Options and correct IDs use the existing website contracts and medical-verification gate. Existing snapshots without this marker retain their original schema/prompt. No old cards are converted, and true/false is not added.

Every omitted source block remains a private, stable archive excerpt. Once used by a later saved episode, its retained source anchor remains available under the source-archive category. Coverage counts measure selected blocks, not medical completeness. Partial episode failures preserve successful model calls and library saves. Replaying identical checkpoints does not append duplicate articles/questions. New files arriving later produce a fresh immutable snapshot; cross-snapshot consolidation still needs additional real-shift validation.

Existing per-recording ASR holds/retries, model/GPU admission and source retention stay in force. Failed detail calls have bounded attempts. Remote sync follows the existing separate clinical authorization gates and never controls whether local extraction can finish. Independent cloud backup remains optional. All generated candidates remain private/draft; no publication command is executed.

The normal Morning Report links the detailed whole-context notes after results are saved. The desktop opener can select a different private review workspace through `~/FieldNotes/config/active-review.json`; it accepts only a FieldNotes read-only review unit and private workspace. Actual workspace paths, clinical contents, source hashes and capability URLs belong only in private continuation notes.
